## A. Never-throw / documented-contract violations  *(real bugs — recommend fixing in 2.14.1)*

These functions are **documented** as never-throwing / graceful, but throw a raw `TypeError` on
nullish or shapeless input. They're agent-facing read/classify helpers reachable from
`renderLandingPage` and the self-describe block, where a **foreign** 402's shape isn't guaranteed.

| id | symbol | doc says | actually | repro |
|----|--------|----------|----------|-------|
| **F-A1** | `classifyChallenge(c, opts)` | *"Never throws."* | throws `TypeError` on `c = null \| undefined` (unguarded `c.accepts`) | `classifyChallenge(null,{network:'eip155:8453',schemes:['onchain-proof']})` |
| **F-A2** | `describeChallenge(c)` | empty accepts *"degrades to a generic pointer"* | throws on `{}` / `{accepts:null}` / `{accepts:undefined}` (unguarded `accepts[0]`); only `{accepts:[]}` degrades | `describeChallenge({})` |
| **F-A3** | `client.estimateCost(url)` | `{ quote, cost }`, never throws | throws `NoCompatibleAcceptError` on a foreign-only 402 (no rail for the client's chain), where `planPayment` is graceful | client on `base`, 402 offers `solana` only |

**Fix (F-A1/F-A2):** guard `const accepts = Array.isArray(challenge?.accepts) ? challenge.accepts : []`
at the top of each (protocol-layer, viem-free). **Fix (F-A3):** catch the no-compatible-rail case and
return a graceful `{ quote:null, cost:… }` (or `null`) like `planPayment`, so the never-throw contract holds.

Characterized green in `suites/12-multichain-agent.mjs` (flip to expect `'ok'` when the guard lands).

## B. Footgun  *(real — recommend fixing)*

| id | what | impact |
|----|------|--------|
| **F-B1** | `createPaymentGate({ amount: '1e3' })` is silently accepted as **1000 tokens** (`1e9` base units), not rejected | a merchant who passes a computed/exponent-form amount string charges 1000× — silent, no error |

Repro: `createPaymentGate({chain:'base',token:'USDC',amount:'1e3',payTo:…}).challenge()` → `accepts[0].amount === '1000000000'`.
**Fix:** reject non-plain-decimal amount strings (no `e`/`E`) with a typed `PipRailError` before `parseUnits`. (Verifies via `expandScientific`'s sibling path — amounts should NOT expand scientific.)

## C. Typed-error conformance  *(ERRORS.md §5 — raw errors instead of `PipRailError`)*

The SDK's own standard (`sdk/ERRORS.md`) says every module reports a thrown **typed** `PipRailError`.
These input-validation boundaries throw a bare `viem`/JS error instead — recoverable but off-standard.

| id | call | throws |
|----|------|--------|
| **F-C1** | `buildWellKnownX402Manifest({ origin, resources:null \| missing })` | raw `TypeError: Cannot read properties of … (reading 'map')` |
| **F-C2a** | `createPaymentGate({ amount: 0.05 })` (a **number**) | raw `TypeError: value.split is not a function` |
| **F-C2b** | `createPaymentGate({ amount: 'abc' })` | bare `Error` from `parseUnits` (not a `PipRailError`) |
| **F-C2c** | `createPaymentGate({ /* no payTo */ })` | bare `Error: requirePayment: no payTo …` (not a `PipRailError`) |

**Fix:** wrap each at the boundary in the appropriate typed error (`UnknownTokenError`-style /
a new `InvalidAmountError`/`InvalidConfigError`), per ERRORS.md §5.

## E. Notes / by-design  *(NOT bugs — recorded so we don't re-litigate)*

- `toMcpPaymentResponse(content, null)` throws — it's a **seller-side projector** only ever called
  with a verified `receipt`, not one of the never-throw reader codecs. Defensive note only.
- base `PipRailError` has `.code === undefined`; only subclasses set a stable code. By design.
- `BRAND` ships as an **object**, not a string (an early test assumption was wrong; SDK is fine).
- `canAfford(url)` returns **true** for a non-paywalled (HTTP 200) URL because `planPayment` returns
  `null` there — arguably correct ("nothing to pay → affordable"); worth a doc line.
- Read methods (`estimateCost`/`planPayment`) throw on the **402-fetch leg** (unreachable host / empty
  URL); the never-throw guarantee covers the **RPC-read** leg, not reaching the resource. Document it.
- `estimateCost` prices the `onchain-proof` rail when a 402 co-offers a gasless `exact` rail, so the
  "gasless → fee 0" property only surfaces when gasless is the selected/only rail. Nuance, not a bug.
- NEAR native fee is 24-dp and exceeds `Number.MAX_SAFE_INTEGER` — correctly **string/bigint-carried**
  (positive confirmation of the safe-integer discipline).
- All 12 chain families emit fully v2-conformant `onchain-proof` challenges with exact BigInt
  base-unit math (suite 14, 328 assertions). The `exact`/`upto`/MCP/A2A transports + receipts +
  payment-identifier dedupe all verified **live on Base mainnet**.

## What the published 2.14.0 got RIGHT (proven, not assumed)

- **Security:** the MCP transport re-derives every field from the **trusted accept** — a forged
  `accepted` (downgraded amount, attacker `payTo`, wrong asset) is re-challenged, never settled/leaked
  (suite 06). The `payment-identifier` **dedupe is real and distinct from tx-replay**: a *fresh* tx
  reusing a seen id is rejected (suite 07, live).
- **Never-throw codecs:** the full `from*/is*/parse*/decode*` battery (34+ hostile inputs incl.
  prototype-pollution payloads) never throws and never pollutes `Object.prototype` (suites 06/10).
- **Replay:** every live settlement (10+ on Base mainnet across all rails/transports) is single-use.
- **API surface:** all 146 documented exports ship and import from the published artifact; `/node`
  subpath works; CJS + ESM both resolve (suite 09).

> Net: 2.14.0 is solid on every security-critical and happy-path property. The findings are
> robustness/contract-polish (graceful degradation + typed errors + one amount footgun) — a clean,
> low-risk **2.14.1** patch. None changes a default or a settled-payment outcome.
