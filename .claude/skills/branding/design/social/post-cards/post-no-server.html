PipRail
no server, by design

This is how PipRail works.
There is no server.

The SDK runs inside your process, against your own RPC node. Nothing routes through us, because there is no us to route through.
WHAT THAT GIVES YOU
✓ MCP access @piprail/mcp
✓ Agentic access 8 agent tools · paymentTools()
✓ Universal x402 client PipRailClient · 29 chains
WHAT RUNS LOCALLY, AND WHAT WOULD NOT
◐ x402 analytics and intelligence discover() reads the open indexes
aggregate stats would need a server
WHAT IT RULES OUT, ON PURPOSE
✕Feedback and review transparencya server, and moderation
✕Reputation and factual rankingmakes us a rating authority over
projects we compete with
✕Advertisement systemsa revenue interest in a table
trusted because we have none
✕Leaderboardsa server, and a game to farm

Why the line is where it is

Reviews, reputation, ads and leaderboards all need the same three things: a server, an account, and someone to moderate it. Add those and PipRail stops being a library you install and becomes a service you join, which is the one thing it was built not to be.
